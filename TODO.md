# KiCode Task & Roadmap Tracking

- [x] **Independent tool calls in one turn overlap (ADR-063)** — the 141s / 18-tool turn was **arithmetic, not a slow model**: `loop.ts` ran the calls in a `for (const call of calls)`, so eighteen independent reads cost eighteen sequential waits. Measured against the same calls: **853ms where 44ms of work was needed**. A turn's calls now resolve in three passes — *decide* (sequential, in call order, approvals asked one at a time and all before anything runs), *launch* (start what may overlap without waiting, wait for each thing that may not), *report* (record every answer **in the order it was asked**). The report order is the constraint the shape exists for: every result lands beside the call it answers, so the message list stays valid and a saved session replays. Running them concurrently but recording by completion would be faster and wrong. **Overlap is a property of the tool, not the turn** — a new `concurrencySafe` marker, **defaulting to false**, set only on `read`/`glob`/`grep`/`recall`, so two writes can never interleave; defaulting off means a tool nobody has thought about does not start overlapping the moment it is registered. Deliberately **not** inferred from `requiresApproval`: an MCP tool on an auto-approved server has no gate and can still write, so those are different questions. A rejection **cannot be reported when it is decided** — `rejectToolCall` pushes into the transcript, so it would land ahead of an earlier call's answer; rejections are carried as slot content and emitted in the third pass, which is why `ToolSlot` exists at all. Every launched promise is wrapped so it cannot reject, or a cancelled turn would take the process down with an unhandled rejection. **Measured end to end: 18×40ms reads, 853ms → 44ms**, transcript in call order in both. Also fixed a **pre-existing flake** in the `@` mention test — a fixed `tick(80)` for a submit that reads a file off disk, missed about one run in five on a loaded machine, so the test asserted on a prompt that had not been submitted yet. Verified flaky on the baseline before touching it, and the fix polls for the condition like the polling already three lines above it
- [x] **A folder per subagent, for its skills (ADR-058)** — the observed failure was a session asked to audit thirteen repositories doing all thirteen itself while `cody-git` sat unused. The roster was present and correct; it carried **one sentence per agent** to judge fit against, and a model weighing that against a task it is already doing keeps doing it. So each agent may have a folder beside its file — `~/.kicode/agents/<name>/` globally, `<cwd>/.kicode/agents/<name>/` per project, the same two scopes and override rule as `agents.json`. **`SKILL.md` is the one fixed name** (its body is the agent's standing brief); **every other `.md` is a skill**, frontmatter optional and the filename is the name when absent, because requiring it makes the folder a chore and a chore is a folder nobody fills in. **The skills go into the system-prompt roster by name and description** — that list is what the routing decision is actually made against — and the child is handed the **paths**, told to read the one that covers its task. Never the bodies: which skill a task needs is not knowable before the task is read. The folder *prepends* to `instructions`, never replaces, or `/agents` would be editing a field nothing reads. A project profile with no folder of its own **keeps** the global agent's skills; overriding who an agent is, or narrowing its permissions, is not a request to strip what it already knew. Verified from outside the process against a real folder: the parent prompt carried the three skills, the child carried the four paths, and a `delegate` call with `agent: cody-git` ran and reported

- [x] **A stopped batch is resumable (ADR-059)** — a cancellation mid-batch is the *ordinary* end of a delegation, and from the next turn it was invisible: the parent had the reports that arrived, no record of the rest, and re-planned from there, so finished work was done twice and a report was lost. The registry already knew — a cancelled child settles `interrupted` — and nothing read it. The next turn now carries a note naming each unfinished child **by agent and goal**, so the task can be re-issued; it rides alongside the user's prompt rather than replacing it. Only `interrupted` and `stalled`: a `failed` child was already reported in the tool result, so re-offering it asks for a retry already offered once. **Offered exactly once**, dropped from the registry as it is handed over — a repeating reminder would have the model re-delegate work it had finished, which is the failure this exists to prevent. **Stated limit**: the work *restarts*. Nothing carries a child's intermediate state across a stop, and that is a larger feature than this one

- [x] **The permission ladder (ADR-060)** — answering `always` to one `bash` command and never to an `edit` is reasonable, and no on/off switch expresses it. Three rungs on a clickable chip below the chat: `[ASK]` (ask before anything that changes files or runs a command), `[EDITS]` (write and edit without asking, still ask before a command), `[ALL]` (no diff, no prompt, no undo, drawn in the error colour). `[ASK]` is the default **on every run** — trust is given, not inherited. One click steps a rung; `/permission ask|edits|all` sets one outright. The rung decides on the **tool, never its arguments**: "does this rung trust this kind of tool" is answerable from the chip, "does this command look safe" is not. Delivered as a **predicate over the app's live mode**, not a value, because a value would mean rebuilding the agent — and rebuilding throws away the approvals already given this session. Announced every time, since the next rung stops asking. The gate itself is pinned in `loop.test.ts` against a real `Agent`: the TUI's agent is a fake with no gate, so a TUI test asserting only that the prompt *did not appear* would have passed against a build where the rung changed nothing
- [x] **Named subagents with a grantable permission (ADR-054)** — the owner's override of ADR-053's "no roles", and a better call: the objection to roles was that a role enum *plus* a per-role model *plus* a role picker is too much surface, not that naming a child is wrong. A profile is the whole of it — a name, one line of description, the specialisation put in front of the child's prompt, an optional model, and a permission level. `delegate` gained an `agent` field, and **the names go into the tool description and its parameter enum**, because that string is the only place a model learns `cody-git` exists; a task names its own, so one batch can send one task to `cody-git` and another to `cody-frontend`. Files are `~/.kicode/agents.json` and `<cwd>/.kicode/agents.json`, the project's overriding by name and *replacing* rather than merging, so a repo can ship an agent and can also narrow a global one's permissions. **Not** a block in `kicode.json`: that file is committed, so a form editing it would rewrite a tracked file behind the user's back. **`bash` is never grantable** — read and edit are the file-shaped permissions, and a child has no approval channel, so a shell would mean a model you delegated to running anything unsupervised, four at a time, with no diff to show you first. Edit is per-agent, opt-in, off by default, and the editor says what it means while it is off. Everything a profile decides is resolved **once** in the delegate tool and passed to the child builder as arguments, because the grant is the one thing here that must not be read twice. An unknown name is **refused with the real ones listed** — falling back would be a substitution the model never asked for and would not know about, so it would report a general-purpose result as the specialist it never ran. The editor is a form, not a wizard: only the field under the cursor carries a hint line, because every field carrying one doubles the height and a form that scrolls to reach its own Save button is a worse form; clicks route through the key handlers so the mouse cannot diverge. Three things the tests found: `\u001b[B` and `\r` in one write arrive as *one key* (the decoder reads the buffer as one escape sequence) so the cursor never moved; Enter inserts a newline because this is the prompt's editor, so Name/For/Model now commit their first line — a name that failed validation over a stray newline would have been a confusing message about characters; and the toggle renders as `no / [yes]` with the live option bracketed, not `[yes] / no`. 1374 tests across 57 files, typecheck clean, verified end to end against the mock — a project-scoped `cody-frontend` with write permission resolved from `.kicode/agents.json` and the child was offered `read, glob, grep, recall, write, edit`, never `bash`.

- [x] **Subagents: the main agent can hand work to child agents (ADR-053)** — built from Hermes' delegation design (MIT, reused with attribution), with two of its choices deliberately rejected. One `delegate` tool and **no roles**: a role enum plus a per-role model is a settings surface nobody gets right, and one `delegation.model`/`baseUrl` pin is one thing to configure — left empty by default, so a fresh install spends no second model's money. A batch runs in parallel and reports in the order asked. **Isolation is the tool list, not a flag**: a child is an ordinary `Agent` holding `read`, `glob`, `grep`, `recall` and nothing else — no `write`, `edit`, `bash`, `remember`, `ask`, or nested `delegate` — so there is nothing to be talked into using; `bash` is out even though a gated read-only command would be allowed, because a child has no approval channel and is refused every gated tool anyway. Verified from outside the process with `MOCK_LOG=1`: children are offered `read, glob, grep, recall`. **No wall-clock timeout** — staleness measures *silence* (450s idle, 1200s in-tool, since a long grep is also silent) and aborts the child on its own signal, or one wedged request would hold the parent open until the session's own budget. **A cap is refused, never applied**: a batch over the turn's remaining budget is an error naming both numbers, and `maxPerTurn` resets each turn. **Nothing fails quietly**: a dead child is a line naming its reason, the rest of the batch still reports, and a child out of turns is `stalled` rather than `completed`. The panel reads data (`Tool.subagents()`, the same contract as `snapshot()`), never prose — a dock above the prompt, two rows plus a count, and `/agents` for the roster and each report in full. Two things found by writing the tests: the roster row was scoped to the whole session, so a second delegation's count included the first's children; and it settled on the *first* child to finish, which would have left the rest to land on a row that no longer existed. Also fixed a regression the new command caused: `/help` was thirteen rows on an 80-column terminal, seven of them a run-on command list, and one more command pushed the keymap off a short screen — it now names the count and points at `/`. `childRunner` lives in `subagent.ts` rather than `app.ts` because `kicode -p "…"` is a supported way to run and delegation silently missing from one of the two doors is worse than missing from neither. 1314 tests, typecheck clean, verified end to end against the mock provider. **Known gap**: a child's tokens ride on its own report but are not charged to the parent's ledger, so `/context` and `/usage` under-report a delegated session — the fix is an `Agent.absorb(other)` the loop calls per settled child.

- [x] **A stamp is not a date, and tracked work outlives the tools (ADR-036)** — two of these were the same mistake ADR-035 named, a stored value answering a question it could not. (a) The `[USAGE]` card printed `session started 2026-10-02T05:38:58.828Z` — the record's own UTC field. It now reads `DD-MM-YYYY HH:mm` on the local clock, and `createdAt` is only ever formatted, never interpolated. (b) The **`[TODO]` chip sometimes not showing**: the plan tools are built fresh with every agent, so a session that was reopened — switched back to, resumed, or rebuilt on a model change — had nothing tracked as far as the chip could tell, while the checklist sat in the conversation. `planFromHistory` replays the transcript's `todo`/`goal` calls through a fresh toolset: exact, not approximate, because both tools only mutate their own state and never touch a file. (c) `/learn` runs the extraction pass **on demand and reports** what landed and what was skipped — the automatic pass is silent by design, so "nothing was added" is only knowable by asking — and `/memory` prints where the brain is, this directory's memory text as the agent actually receives it, and the other projects recorded. (d) **A key cannot arrive quietly**: `scripts/check-secrets.mjs` scans staged content for real provider shapes, `.githooks/pre-commit` runs it locally, and CI runs it over every tracked file so a clone that never installed the hook is covered anyway. Fixtures say `kicode-secret-ok` **on the matching line** — per-line on purpose, since a file-wide marker is somewhere a real key could hide. Also de-flaked the timing-dependent TUI tests, which failed three tests on one full-suite run and none on the next with identical code.

- [x] **A steer you can see, and a queue you can type at (ADR-035)** — the follow-up to ADR-034, plus three unrelated reports. (a) The `steered` event moved from where the click happened to where the words **join the transcript**, so a message added while a slow tool is still running now reports itself instead of the tile just vanishing; the spinner names the wait (`thinking… · +1 to read`), and a turn that dies before reading them **puts them back** at the front of the queue rather than dropping words the user typed. (b) Bare `/queue` opens a list the keyboard can work — `ctrl+a` steer, `ctrl+x` drop, `enter` take the message back into the prompt to rewrite — and it is the one command that runs **while a turn is in flight**, since the queue is only ever non-empty then. (c) `/compact` now means compact: it was returning "nothing to compact" on any session already inside the target, so the target is halved when the pass is asked for by name. (d) `DEFAULT_COMPACT_AT_TOKENS` = **150 000** with the window at 200 000, so auto-compaction fires at 150K — the window has to exceed the ceiling or the window would decide and the ceiling would never trigger. (e) Dates are local and in the user's own format: `iso.slice(0, 10)` was the UTC day (a session from last night read as the day before), the month heading was a hardcoded English list, and the memory stamp was UTC too.

- [x] **The agent learns without being asked (ADR-033, owner issue #2)** — "skills not auto-saving" was not a bug: `remember` is a tool the *model* chooses to call, so a session only taught the brain when the model thought of it. Built the Phase 2 pass designed in ADR-031/032: after a finished turn, one extra request on the user's own key asks "what here is worth keeping?" and files up to five items through the `remember` tool's own writers. Additive (an existing skill is skipped, a duplicate memory is skipped), off the critical path (fire-and-forget, quiet unless something was added), skipped entirely for a transcript too short to hold anything, and gated by `"learning": "auto"|"off"` / `KICODE_LEARNING=off`. **Also closed a real gap found while building it**: `saveMemory` had no secret check of its own, so the automatic pass would have written a key with no user in the loop — `looksLikeSecret` is now shared and applied on both paths.
- [x] **Plan mode stopped refusing commands that only read (ADR-033, owner issue #1)** — the classifier was too strict. It now strips assignments in front (`FOO=bar ls`), allows plain filters (`uniq`, `cut`, `tr`, `nl`, `basename`, `dirname`, `realpath`, `readlink`, `printenv`, `id`, `ps`) while keeping out the ones that can rewrite their input (`sort -o`, `sed -i`, `tee`, `xargs`), and allows `git branch`/`tag`/`remote`/`config` only when they name nothing or carry a listing flag — `git branch feature` and `git config k v` are still refused, as are writing flags. `node -e` and `npm test` remain refused: they run code.
- [x] **Session isolation, a `[USAGE]` button, and the queue's controls tidied (owner issues #3–#7)** — (3/4) **`ADD[+]` is removed** from the box: a message is queued by pressing enter while a turn runs (or with `/queue`), so the box now carries only `UPLOAD[+]`, the one click-only action the keyboard cannot do. (5) a **`[USAGE]` chip on the state row** — always present, beside `[TODO n/m]` — opens a card with this session's messages, tool calls, context tokens, budget and age; `escape` closes it. (6) **rename now survives a switch**: `switchSession` set `title = null`, so the next `save()` re-derived a title from the first message and silently overwrote the chosen one; it now reads the record's own `title` and `createdAt` back. (7) **sessions no longer share state**: the queue, attachments, plan panel, recovery card, notices, pause, editor text and the spinner are reset on a switch or a new session, and a turn is bound to the session it started in, so its events can never be written into the one being opened. 1047 tests, typecheck clean, build 517.03 KB.
- [x] **A fresh user's brain is created, not demanded (ADR-031)** — owner's question: *"for a new user with no `ki-agent-brain`, how does it learn and build skills over time?"* The honest answer was that it could not: a brain was found only via `KI_BRAIN_PATH` or an upward walk for a directory named `ki-agent-brain`, there was no config key and no default, and `remember` refused with "no brain found" when neither existed — so a new user's first save failed and nothing accumulated. Built: resolution order **`KI_BRAIN_PATH` → `brain` in `kicode.json` → existing `ki-agent-brain` walk → `~/.kicode/brain`**; `ensureBrainDir` makes `remember` **create** the configured path or the default `~/.kicode/brain` on the first save (the walk is never a creation target); a validated `brain` config key read synchronously (the briefing has no `await` on its path) with `~`/relative handling; and `--help` now names `KI_BRAIN_PATH` and the default. Existing brains are untouched — the owner's `ki-agent-brain` still wins. Phase 2 (an automatic extraction pass over the transcript) and Phase 3 (an always-injected "taste" layer + `/memory` and `/taste`) remain open.
- [x] **The brain is read back, and the agent knows when to save (ADR-030)** — owner asked for the agent to be "more intelligent … know when to remember and store data". The real gap was recall: the brain was write-only, so a fact saved in one session reached the next only if the user typed `@project:…`. Built: (1) a bounded **brain briefing** injected into the system prompt at session start — this project's memory text plus skill names/descriptions; (2) a **`recall` tool** to load a full skill/memory by name or by remembered words; (3) an explicit **save-when / never-save policy** replacing the one vague prompt line, including "add to this project's memory rather than repeating it"; (4) **`action: "update"`** so a skill can be corrected deliberately while a plain save still never overwrites; (5) the skill reader now walks recursively, so categorised skills in a maintained brain are found. Also fixed while here: the compaction planner ignored the system prompt's size, so a longer prompt landed sessions at target-plus-the-prompt; and quoted frontmatter descriptions showed their quotes in the briefing and `@skill:` list.
- [x] **TODO button + plan panel (ADR-029)** — owner's request. The state row carries a `[TODO n/m]` chip whenever the plan tools hold work (a running goal's subtask progress is preferred); pressing it opens a narrow card on the right, just above the input box, with the checklist (`✓`/`◐`/`○`), a progress bar, and the goal's status/title/subtasks/current task. `esc` or its `[×]` closes it. - [x] **OpenCode 403 diagnosed as a client restriction (ADR-029)** — owner reported opencode.ai free models failing with 403 again. - [x] **The turn continues while tracked work remains (ADR-028)** — owner's items 2 ("understand when to ask vs continue") and the deeper half of issue 8. `Tool` gained an optional `pendingWork()`, implemented by the `todo` and `goal` tools; `loop.ts` reads it before accepting an answer and, if work is still open, pushes a user nudge and yields `continued: "work"` instead of `done("complete")`. The system prompt now says to work to the end of the task in one turn and to use `ask` only for genuine user decisions (pick a default and say what was assumed otherwise). The transcript and one-shot mode render the new reason as `tracked work is not finished — asking it to carry on`.
- [x] **The message queue is visible and controllable (ADR-028)** — owner's item 3.
